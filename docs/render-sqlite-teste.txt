RENDER (SQLite escolhido para testes)
1. Publique o código e todas as partes/manifesto da pasta deploy no repositório usado pelo serviço.
2. Em Environment, deixe DATABASE_URL ausente.
3. Configure CATALOG_SEED_PATH=deploy/catalog.sqlite.gz
4. Configure SOURCE_ENCRYPTION_KEY com o MESMO valor de instance/source-library.env local.
5. Copie SOURCE_ALLOWED_HOSTS desse arquivo local para a variável de mesmo nome no Render.
6. Preserve o token TMDB e SECRET_KEY existentes; mantenha APP_ENV=production.
7. Serviço Docker: use o Dockerfile incluído.
   Serviço Python: build = pip install -r requirements.txt
   start = python -m flask --app run db upgrade && gunicorn --workers 1 --threads 4 --timeout 30 --bind 0.0.0.0:$PORT run:app
8. Após um deploy com filesystem limpo, o backend restaura o catálogo automaticamente.
   Registre uma conta no site para testar o player (a resolução exige login).

COMANDOS LOCAIS (dentro da pasta do projeto, Python com requirements.txt instalado)
Criar/retomar o catálogo completo sem consultar TMDB:
python -m flask --env-file instance/source-library.env --app run sources build-catalog

Continuar os metadados de todos os pendentes:
python -m flask --env-file instance/source-library.env --app run sources sync-all
Não execute outra cópia enquanto o processo atual estiver ativo.

Ver progresso:
python -m flask --env-file instance/source-library.env --app run sources status
Logs: instance/catalog-sync.log e instance/catalog-sync-errors.log.

Exportar um snapshot atualizado, após o enriquecimento avançar:
python -m flask --env-file instance/source-library.env --app run sources export-sqlite deploy/catalog.sqlite.gz --split
Depois publique novamente o arquivo. Os próximos metadados locais não chegam ao Render sozinhos.

Verificar uma fonte pelo backend, sem imprimir a URL privada:
python -m flask --env-file instance/source-library.env --app run sources check ID_FONTE

LIMITES REAIS
O backend resolve redirects, verifica HTTPS, identifica MP4/HLS e diagnostica falhas.
A mudança HTTP->HTTPS só é aceita depois de uma requisição HTTPS bem-sucedida.
URLs assinadas são resolvidas ao assistir, em vez de salvas como permanentes.
Não há proxy de filmes nem transcodificação FFmpeg no Render gratuito.
Drive /view e /preview continuam sendo páginas; não se tornam arquivos MP4 por este processo.
HLS pode exigir CORS nos segmentos/chaves; codecs precisam ser suportados pelo aparelho.
Fornecedores podem bloquear o IP do servidor ou entregar links expirados.
A integração de todas as fontes não significa que todas as mídias foram reproduzidas ou validadas.
A URL final é visível ao navegador; criptografia protege o armazenamento, não oculta o tráfego de reprodução.

ATUALIZAÇÃO: ADMINISTRADOR E PROCESSAMENTO COMPLETO
Com ADMIN_USER, ADMIN_EMAIL e ADMIN_PASSWORD configurados no Render, o administrador
é recriado automaticamente após a restauração do banco. A senha deve ter ao menos 8 caracteres.
As credenciais não são incluídas no snapshot e não devem ser publicadas no GitHub.

O processamento completo é executado por scripts/complete_catalog.py, em três etapas:
1. Capas e informações das séries; 2. Filmes pendentes; 3. Detalhes dos episódios.
Com --publish, um snapshot é exportado e enviado ao GitHub ao concluir cada etapa.
O script precisa do computador ligado, internet e autenticação Git já autorizada.
Estado: instance/catalog-job.json; log: instance/catalog-complete.log no clone de publicação.
Falhas de rede têm novas tentativas; em falha persistente, o estado fica failed e a fila pode ser retomada.
Correspondências ambíguas não recebem informações inventadas.

ACELERAÇÃO DO PROCESSAMENTO
A fila inteira é processada sem limite de quantidade de títulos/episódios.
O padrão agora faz 8 consultas em paralelo, mantendo apenas um escritor no SQLite.
Os trabalhadores têm conexões HTTP próprias e cache em disco/memória.
Quando o TMDB responde 429, todos respeitam a pausa indicada pelo fornecedor.
A opção --workers permite ajustar a concorrência; --limit só é usado para testes explícitos.
O log mostra elapsed_seconds e items_per_minute em cada atualização.
Teste local: 20 títulos em 25,41 segundos no fluxo serial;
50 títulos em 9,02 segundos no paralelo. Amostras distintas; não é uma previsão de duração total.
